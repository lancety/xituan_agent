# Site · 平台首页（未锁商户 · 导流发现）

Last updated: 2026-11-15

索引：[`site.md`](./site.md) · 源码：`(consumer)/page.tsx` → `HomeClient` / `HomePlatformSpotlight`

## 产品定位（已澄清）

| 表面 | 作用 |
|------|------|
| **平台首页**（本页） | 用户打开 Site / App / 小程序且 **未锁商户** 时的发现页：导流到感兴趣的店铺、活动、商品 |
| **商户主页 / 子域** | 商户自有推广链接落地；**锁业务范围**，不回到平台首页 |

成功指标（平台首页）：进入某商户域或点进活动/商品，而不是「在平台首页完成整单」或「必须留下看招商」。

## 信息架构（已拍板方向）

| 区块 | 策略 |
|------|------|
| 已入驻商户 | **有限量**推荐 |
| 近期团购 / 预定 | **有限量**推荐 |
| 热门/推荐商品 | **无限下拉懒加载** |
| 扩展检索 | 顶栏搜索（类型 + 框） |
| 小程序 | **降权但可触达**（见下节）；不做与入驻并列的双 hero |
| 入驻/会员 | B 次要入口（顶栏/页脚/指南页），不与 C 发现同权双 spotlight |

不做「查看更多」目录主路径；深挖靠搜索 + 商品无限流。

## 小程序曝光（无限流约束 · 已拍板方向）

**禁止**：放在无限商品列表**下方**或仅页脚——商品一多等于永不曝光。

**推荐组合（降权双 hero + 仍保证曝光）**：A 常驻顶栏 + B 边界轻条（规格见下）+ C 可选流内一刀。

不要：半屏双卡 hero、列表底、随每一屏重复的贴片。

### A · 长什么样（常驻入口 · 分端）

复用 `WechatMiniprogramQrTrigger`（点开 popover + ~200px QR），**不要**半屏卡。

**硬约束（现状）**：`<768px` 时 `.site-consumer-header-desktop .site-consumer-topbar` 为 `display: none`，底栏是 `MobileBottomNav`。  
→ **只把 A 放进 `SiteTopBar` = 手机上没有 A**。必须桌面 / 移动分挂载。

| 端 | 挂哪 | 规格 |
|----|------|------|
| **桌面 ≥768** | `SiteTopBar` 右侧（`SiteQuickNav` 旁） | 顶栏高 34px；触发器高 ≈26–28px；文案「小程序」；紧凑 padding（现成 8×14 会撑破顶栏，需 topbar 变体） |
| **移动 &lt;768** | **不要**依赖 TopBar | 见下「移动 A」 |

**移动 A（推荐，按优先级）**：

1. **首选**：平台首页 `ConsumerLogoSearchBar`（mainbar）右侧加紧凑触发器——首页移动端仍显示大搜索行，用户未滚列表也能看到；popover 向下展开，注意别挡搜索框过久。  
2. **不要**默认塞进 `MobileBottomNav` 第五项（现已首页/消息/购物车/订单/我的，再加会挤、且与「发现」任务抢位）。若要底栏：进「我的」或溢出菜单，不当主 Tab。  
3. **移动更倚重 B**：边界轻条在手机上是「未进无限流前必经」的主曝光；A 负责再找一次。

展开：移动用 tap + `is-open`（组件已支持）；popover 在窄屏建议 `left: 0; right: 0` 或居中，避免 `right: 0` 裁切；QR 可略缩到 160–180px。

**不是**：移动顶栏大码、底栏第六主 Tab、prominent 大按钮占满搜索行。

### B · 有多小（有限轨 ↔ 无限商品 之间）

对比现状 spotlight 小程序卡内 QR **168px** + 大标题，B 只做 **单行/一行半横条**：

| 项 | 规格 |
|----|------|
| 整条高度 | **约 56–72px**（含上下 padding）；目标 ≈ 现双 hero 小程序卡高度的 **≤1/4** |
| 布局 | 横排：左文案（1 行主句 + 可选 1 行次句）· 右小 QR |
| QR | **56×56 或 64×64**（可扫、不抢戏）；不要 168 |
| 文案 | 主句 ≤ 16 字级，如「也可在微信小程序浏览」；次句可省 |
| 背景 | 用 `--bg-raised` / 细边框，**一张条**不是卡片网格；无 kicker、无双 CTA |
| 宽度 | 内容区全宽，与 `site-section` 同宽 |

用户滚完商户/团购/预定后、进入商品无限流前 **必看一次**；之后靠 A 随时再开。

## 受众张力（设计须显式处理）

平台同时服务 **入驻商户（B）** 与 **发现消费者（C）**。  
C 打开未锁首页时，主视觉应服务导流；B 入驻可次要入口（顶栏/页脚/独立指南页），避免双 primary hero 抢发现。

## 空态 / 失败

失败 ≠ 无货；无限商品流需明确加载中 / 失败重试。

## 信任档

商户卡：[`site-merchant-trust.md`](./site-merchant-trust.md)

## 推荐页面构图（基于 L0 + 本页模型）

从上到下（**mobile first** 单列；平板/桌面加宽栅格，不断开任务）：

```text
[ Chrome ]
  桌面：TopBar（主题/语言 + 首页/购物车… + A 小程序胶囊）
  移动：隐藏 TopBar → Mainbar（Logo + 搜索 + A 小程序）+ BottomNav
[ 发现主路径 — 首屏起就是推荐，无双 hero ]
  ① 已入驻商户（capped）— 卡 + 普通店/品牌店 soft badge
  ② 近期团购（capped）
  ③ 近期预定（capped）
[ B 小程序边界条 56–72px · 左文右 56–64 QR ]
[ ④ 推荐商品无限懒加载 ]
[ Chrome：≥768 TopBar「商家入驻」+ 小程序 A；移动首页不放 ]
[ 移动：用户主页「版本」上方 promo section：小程序 QR + 喜团顾客 App 下载 + 商家入驻 ]
[ 页脚：法律 +「商家入驻」链；勿大卡双 hero ]
```

### 删 / 改现件

| 现件 | 处理 |
|------|------|
| `HomePlatformSpotlight` 双卡（入驻+大 QR） | **移除出首页主路径**；入驻/小程序：≥768 TopBar；移动 → **用户主页** promo；页脚弱链；B 边界条仍在首页商品流前 |
| section 等权标题 | 保留结构；用主青做标题下划线/选中，加强「发现」可读性（见 brand） |
| 商品流 | 保持无限懒加载；loading/失败态可见 |

### 色与氛围（已落地 · 亮暗都要）

| 元素 | 用色 / 行为 |
|------|-------------|
| `--color-primary` / 链 / 顶栏入驻 CTA | 亮色字标青 `#18C0C8`；暗色 ink/fill（勿在亮色用暗色加深青绿） |
| 顶部品牌带 | 仅首屏 ~280px 青→微黄 wash + 圆形装饰，向下淡出（`.site-home-discovery-band`；同款 `.site-theme-content-band` 用于商户布局 / 店招布局 / 购物车） |
| 发现跳转 chips | 已移除；色相合同见下「轨标题」 |
| 轨标题 | 左侧 4px 分轨色条：**商户**品牌青 · **团购** `--mode-offer` 青 · **预定** `--mode-preorder` 琥珀 · **商品/零售** `--mode-retail` 紫（见 [`brand.md`](./brand.md)） |
| 移动 capped 轨 | 横滑 `scroll-snap`；商品无限流仍栅格 |
| 商户 logo | 圆形 + 青环 |
| 团购/预定 | 进行中且 ≤72h 结束 → 黄「即将结束」（真实 endDate） |
| B 条 | 商品流前；装饰青对齐 brand cyan |
| 商户信任档 | soft badge（[`site-merchant-trust.md`](./site-merchant-trust.md)） |

勿再写回 GitHub 蓝；勿整页铺渐变；勿显示 capped 数量当总数。

### 断点注意

- 移动：首屏 = 搜索 + 商户轨起；A 在 mainbar；B 在进商品前必经。  
- 桌面：TopBar 有 A；卡片栅格按 [`site-theme.md`](./site-theme.md)。  
- 勿把 B 放到商品无限流下方。
